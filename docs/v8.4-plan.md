## Scope

### Issue 1 — readback binding rehydration

**Root-cause analysis:** persisted Codex poll state can survive restart in
an impossible binding state: `requires_turn_id=true`,
`bound_turn_contaminated=true`, empty `bound_turn_id`/`current_turn_id`,
empty `reply_buffer`, while the session jsonl continues to advance. In
this state, `binding.py` rejects assistant/terminal entries before they
can populate reply state, so the dispatcher never observes
`reached_terminal=true`.

**Diagnostic plan (one diag round, separate from any code change):**
1. Add a one-shot diagnostic dump emitting (a) `state.offset`,
   (b) line count + last entry summary at that offset, (c)
   `bound_turn_id`/`current_turn_id`/`requires_turn_id`, (d) which
   guard predicate is rejecting matches.
2. Reproduce locally: run `ccb ask agent2 "[CCB_HEARTBEAT]"`,
   `ccb kill -f && ccb`, observe diag dump.
3. Confirm hypothesis or refine before patching.

**Fix shapes (post-R2 update 2026-05-05):**

- **A) Replay/rebind recovery:** on restart or guarded poll-time
  recovery, replay the session jsonl from offset `0`, bind only to this
  job's `CCB_REQ_ID` anchor, then accept assistant/terminal entries only
  for the turn discovered from that anchor. Gate to `reply_buffer == ""`;
  do not replay over an already-started reply. Add a
  `replay_in_progress` phase flag on `CodexPollState` or equivalent so
  replay is non-reentrant across concurrent ticks. Viable only when diag
  proves the full reply is already recoverable; higher state-machine
  risk than C.

- ~~**B) Trailing read bypass**~~ — **DROPPED:** bypassing turn binding
  from current offset creates a second identity model beside
  `assistant_entry_matches_bound_turn` /
  `terminal_entry_matches_bound_turn`; likely to misattribute old or
  foreign assistant output.

- **C) Recommended baseline:** detect the impossible state at both
  layers — startup-time scan for contaminated incomplete executions
  older than `ccbd.start_time`, AND poll-time tick check for
  contamination occurring during the current daemon lifetime. Abandon
  the execution with a phase-2 failure record so the queue progresses.
  Lowest-risk because it does not mutate Codex binding semantics.

**A vs C decision rule after diag:**

1. Choose A only if the diag dump proves the session jsonl contains this
   job's `CCB_REQ_ID` anchor.
2. The same dump must show a matching assistant entry after that anchor.
3. The same dump must show a matching terminal entry after that anchor.
4. The execution must have `reply_buffer == ""` for at least N
   consecutive ticks; default N=3, configurable if implemented.
5. If any of 1–4 fails, choose C.

**Quarantine requirement for C:** abandon must first quarantine trailing
session jsonl evidence.

- Create `~/.gstack/quarantine/` with `mkdir -p` on first abandon;
  permission-denied logs warning and abandon proceeds.
- `~/.gstack/quarantine/<agent>-<job_id>-<ts>.jsonl` containing the last
  N raw session entries; default N=50, `CCB_QUARANTINE_TAIL_ENTRIES`.
- Adjacent manifest:
  `~/.gstack/quarantine/<agent>-<job_id>-<ts>.manifest.json` with
  `agent`, `job_id`, `inbound_event_id`, `session_path`, `offset`,
  `created_at`, entry count, and failure reason.
- 7-day TTL eviction; `CCB_QUARANTINE_TTL_DAYS`.
- 100MB total cap, oldest-first eviction; `CCB_QUARANTINE_SIZE_CAP_BYTES`.
- Permission-denied path: log warning to `ccbd.stderr`, abandon proceeds
  anyway (do not block queue progress on quarantine failure).
- Operator recovery: parse the raw quarantine jsonl with the same
  `extract_entry`-compatible Codex entry normalization used by the
  readback path; do not rely on a fixed `.assistant_message` field.

**What already exists (reuse) — Issue 1:**

### Issue 2 — claude paste-collapse

**Root-cause:** confirmed in memory; `_paste_via_buffer` sends `Enter`
once but claude code v2.1.126 with bracketed paste needs a second
Enter (the first closes the paste, the second submits).

**Fix shape (locked by eng review 2026-05-04):** add an
`extra_enter: bool = False` kwarg to
`TmuxTextSender.send_text(pane_id, text, *, extra_enter)` at
`lib/terminal_runtime/tmux_send.py:24`. When True, after the
existing `send-keys ... Enter` (line 57), sleep `CCB_TMUX_ENTER_DELAY`
(default 0.5s — same env var the existing fire uses) and send a
second `send-keys ... Enter`. Caller (the agent runtime layer
that owns provider awareness) sets `extra_enter=True` for claude
panes only. TmuxTextSender stays provider-agnostic.

Tests:
1. `test_terminal_runtime_tmux_send.py` — add a case for the
   default `extra_enter=False` branch (codex path) asserting
   exactly 1 `send-keys Enter` call.
2. `test_terminal_runtime_tmux_send_extra_enter.py` (new) —
   `extra_enter=True` asserts 2 `send-keys Enter` calls separated
   by the configured delay; assert delete-buffer still fires
   in the finally clause.
3. Caller integration: assert agent runtime invokes `send_text`
   with `extra_enter=True` for claude provider, False for codex.

### Issue 3 — cmd pane "target pane has exited"

**Root-cause analysis:** cmd reply delivery can hold a stale pane id
long enough to send to an exited pane. The current discovery path caches
pane ids for `_CMD_PANE_CACHE_TTL = 30.0` at
`preparation_service.py:784`. The current liveness path invalidates on
dead pane at `preparation_service.py:220`, then defers re-resolution to
a later tick. That is too weak for restart/pane replacement races.

**Diagnostic plan (one round):**
1. Probe ccbd to log the actual `cmd_pane_id` value the dispatcher is
   sending to. Add a one-shot `_logger.warning` at the entry of
   `_deliver_cmd_replies` printing `discovered_cmd_pane_id` and the
   `is_alive` result.
2. Compare against startup_report.json `bootstrap_cmd_pane`.
3. Confirm whether discovery returns a stale id, an inactive
   window-target, or correct `%2` that fails for a different reason.

**Fix shapes (post-R2 update 2026-05-05):**

- **A) Primary: fresh-at-send invariant.** Do not trust cached cmd pane
  ids at injection time. For each delivery sweep that needs a real
  pane, resolve the cmd pane from tmux metadata / `__ccb_ctl`
  role+slot+project id, check `is_alive`, then send. Cache only within
  that single `_deliver_cmd_replies_impl` sweep after liveness passes.

- **B) Fallback safeguard:** if a resolved pane fails liveness or send
  raises `target pane has exited`, invalidate, immediately re-resolve
  once, re-check liveness/readiness, and retry the same reply once. If
  the retry cannot prove a live ready pane, stop the sweep to preserve
  ordering. After K consecutive sweep stops on the same inbound event,
  abandon that event with phase-2 failure; default K=3 via
  `CCB_CMD_REPLY_MAX_RETRIES`.

- **C) Optional cleanup:** clear cached `cmd_pane_id` during
  `ccb kill -f` teardown. Not the fix; only reduces stale state for one
  shutdown path and does not cover daemon-alive pane replacement.

**What already exists (reuse) — Issue 3:**
- `_discover_cmd_pane_id`, `_lookup_cmd_pane_id`,
  `_invalidate_cmd_pane_cache`, `_get_tmux_backend` in
  `reply_delivery_runtime/preparation_service.py`.
- Fix A should mostly skip the cache branch in `_discover_cmd_pane_id`
  and call `_lookup_cmd_pane_id` directly at injection time; this
  reuses the existing fresh lookup already used by diag at
  `preparation_service.py:835`.
- Existing stop-on-defer ordering rule in `_deliver_cmd_replies_impl`.
- Existing delivered-reply cache; do not weaken duplicate-injection
  protection.

### Issue 4 — orphan lease wedge (added post-canary 2026-05-04 KST; SHIPPED)

**Status:** SHIPPED as PR #6 (`feat/v8.4-lease-recovery`, base `v6`).
Two commits: `b0232ed` (initial) + `b2ca22e` (R2 codex review fixes).

**Root-cause (three layers):**
- `_release_matching_lease` (`terminal.py:89-97`) skips silently when
  `lease.inbound_event_id != current.inbound_event_id` at terminal time
  — finalizing through a non-aligned path orphans the lease.
- `DeliveryLease.expires_at` exists in the schema (`models.py:76`) but
  no code path writes a TTL — orphaned leases persist indefinitely.
- `_mailbox_facts` (`mailbox.py:44-50`) derives `mailbox_state` purely
  from `lease.lease_state == acquired` with no liveness check on the
  underlying event — orphan keeps mailbox stuck `delivering` forever.

**Fix shape (locked + shipped):**
- New pure classifier `classify_lease(service, lease)` in
  `lib/mailbox_kernel/service_runtime/lease_validation.py` returning
  `active` / `orphan` / `inactive` based on lease state + underlying
  event terminality.
- `refresh_mailbox` removes `orphan` from disk (the side-effect).
- `_has_conflicting_lease` blocks only on `active` (so first claim
  after restart succeeds without an extra refresh tick).
- `_fallback_lease_version(prior, lease, status)` returns
  `max(prior_version, orphan.lease_version)` so `next_lease_version`
  stays monotonic across orphan recovery.

**Tests (8 new in `test/test_v2_mailbox_kernel_orphan_lease_recovery.py`):**
- consumed/abandoned/missing event → orphan dropped on refresh
- other pending events keep mailbox blocked
- live delivering event lease preserved
- recovers across kernel restart
- first claim after orphan succeeds without extra pass
- lease version monotonic across recovery

**Codex review:** R1 caught two correctness bugs (first-claim-fail on
direct path + version monotonicity loss when no prior mailbox record).
R2 (after fix) → "no discrete bugs introduced." See PR #6 description
for full review trail.

**Live canary:** built `codex-dual.v16`, install rotation, ccbd
restart on statusline; agent1 lease v84→v85, agent2 v64→v65; agent3
heartbeat round-trip clean.

### Issue 5 — execution_state wedge (added post-canary 2026-05-04 KST; queued)

**Status:** queued as next PR (`feat/v8.4-execution-recovery`, base `v6`).

**Root-cause hypothesis (same RCA pattern as #4 at executions/ layer):**
- `execution_state` records with `bound_turn_contaminated=true` survive
  ccbd restart with no TTL and no startup-time scan that abandons stale
  records.
- Recovery currently only happens via the 3-attempt `pane_dead` retry
  path, which is the wrong layer (assumes pane death; the actual fault
  is contaminated turn binding from prior process).
- 7 ancient stale executions on disk in `/home/speed/operational/statusline/.ccb/ccbd/executions/`
  serve as concrete evidence: `job_08d9561d5d12, 0bf121459cd2,
  401059ac1bc3, 410d0a95c186, 4687b45b8209, 51efce9be8aa, e8fa626c5fa4`.

**Likely fix shapes (TBD post-implementation):**
- A) TTL on incomplete `execution_state` records (write on creation;
  startup scan honors expiry).
- B) Startup-time scan abandoning executions where
  `bound_turn_contaminated=true AND mtime < ccbd.start_time`.
- C) Both (belt-and-suspenders): TTL writer + startup scan.

Estimated scope: ~30 lines + 4-6 tests. Independent of Issue #4 surface
(different module).

**Open question for #5:** include a deferred TTL writer for
`DeliveryLease.expires_at` (third RCA layer of #4) in this PR for
parity, or keep it strictly to executions/?

## Acceptance criteria

(Updated post-R2 2026-05-05 to cover silent-failure modes flagged in
codex+claude dual review.)

- `ccb ask agent1 "[CCB_HEARTBEAT]"` and `ccb ask agent2 "[CCB_HEARTBEAT]"`
  round-trip to cmd after fresh restart, AND their source jobs become
  terminal or the next mailbox claim is possible.
- A contaminated empty-buffer Codex execution either recovers the real
  reply via anchor-bound replay OR is abandoned with phase-2 failure
  telemetry plus quarantine manifest/raw tail.
- Replay/rebind tests prove no binding to old turns, latest unrelated
  turns, or foreign `CCB_REQ_ID` anchors.
- Cmd delivery handles daemon-alive pane replacement: old cmd pane
  exits, new `__ccb_ctl` cmd pane appears, pending reply sends to the
  new live pane without waiting for cache TTL. Prefer mock
  `TmuxBackend` with controllable pane lifecycle; real-tmux integration
  is optional and marker-gated.
- Cached delivered replies are not injected twice after restart or
  repeated sweep ticks.
- The 8 queued cmd `task_reply` events drain automatically on the first
  sweep tick after restart.
- No `target pane has exited` appears in `ccbd.stderr` after restart.
- Post-run state inspection shows no stale `DELIVERING` cmd reply
  events caused by pane failure and no stuck `INCOMPLETE` execution
  records caused by the contaminated binding wedge.
- Cmd-delivery suite stays at 84+ pass / 1 skip; add focused tests for
  fresh-at-send resolution, stale retry once, stale retry abandonment
  (K=3), cache no-duplicate behavior, contaminated execution
  abandon/quarantine, and replay misbinding rejection.
