## Problem statement

After v8.3.3 (R1–R4) deployed cleanly, the canary on `codex-dual.v14`
exposed three production issues that all block "normal prompt injection"
into the agent panes. They are unrelated to the cmd reply head-of-line
fix and need to be addressed before the trio (agent1 codex, agent2
codex, agent3 claude) is usable end-to-end without manual workaround.

| # | Issue | Pane(s) blocked | Memory ref |
|---|-------|------------------|------------|
| 1 | LogReader binding rehydration after `ccb kill -f` restart misses session jsonl entries → `reply_buffer=""` forever → dispatcher locked in `delivering` state | agent1, agent2 (codex CLI) | `project_ccbd_codex_session_readback_partial.md` |
| 2 | claude CLI bracketed paste needs a 2nd Enter; ccbd `_paste_via_buffer` only sends one | agent3 (claude CLI) | `project_ccbd_claude_paste_collapse_stuck.md` |
| 3 | cmd reply delivery fails with `target pane has exited` × N events even though `tmux send-keys -t %2` works manually — cmd pane discovery returns stale id | cmd reply path (every reply on a fresh restart) | newly observed 2026-05-04 KST canary |

Issue #3 surfaced during v8.3.3 canary; needs root-cause before being
slotted into either v8.3.x or v8.4. Putting it in v8.4 by default.

## Scope

### Issue 1 — readback binding rehydration

**Root-cause hypothesis:** `bound_turn_contaminated=true` paired with
`requires_turn_id=true` and empty `bound_turn_id`/`current_turn_id`
suggests the binding state from pre-restart is restored but the
post-restart LogReader can't satisfy the turn_id requirement against
the session jsonl. The contamination flag traps the binding in a state
where new entries are read past, never matched, and the dispatcher
sees no `reached_terminal=true`.

**Diagnostic plan (one diag round, separate from any code change):**
1. Add a one-shot diagnostic dump emitting (a) `state.offset`,
   (b) line count + last entry summary at that offset, (c)
   `bound_turn_id`/`current_turn_id`/`requires_turn_id`, (d) which
   guard predicate is rejecting matches.
2. Reproduce locally: run `ccb ask agent2 "[CCB_HEARTBEAT]"`,
   `ccb kill -f && ccb`, observe diag dump.
3. Confirm hypothesis or refine before patching.

**Likely fix shapes (TBD post-diag):**
- A) On restart, if execution is `incomplete` and binding is
  contaminated, FORCE rebind: re-derive turn_id from session jsonl
  head, clear contamination flag, restart LogReader from offset 0.
- B) Add a "session jsonl trailing read" path that walks the file from
  current offset to EOF on each tick when `reply_buffer == ""` and
  `last_rescan - request_anchor_age > N seconds`, bypassing the
  turn_id binding for this corner case.
- C) Detect the impossible state explicitly (`requires_turn_id=true`
  + `current_turn_id=""` + `last_rescan` advancing) and abandon the
  execution + emit a phase-2 failure record so the queue progresses
  (cmd reply path's R3-style abandon, applied to agent task_request
  path).

**Locked by eng review 2026-05-04: if fix C is selected, abandon
MUST quarantine the trailing session jsonl entries first.** The
assistant's actual reply is in the file already (e.g., agent2's
1.1MB scanned session jsonl contains the answer); abandon without
recovery loses real data. Add:

- `~/.gstack/quarantine/<agent>-<job_id>-<ts>.jsonl` containing the
  last N session jsonl entries (default N=50, configurable via
  `CCB_QUARANTINE_TAIL_ENTRIES`).
- 7-day TTL eviction (default; `CCB_QUARANTINE_TTL_DAYS`).
- 100MB total size cap with oldest-first eviction
  (`CCB_QUARANTINE_SIZE_CAP_BYTES`).
- Permission-denied path: log warning to ccbd.stderr, abandon
  proceeds anyway (do not block queue progress on quarantine
  failure).
- Operator recovery: `jq '.assistant_message?' <quarantine-file>`
  surfaces the lost reply text.

### Issue 2 — claude paste-collapse

**Root-cause:** confirmed in memory; `_paste_via_buffer` sends `Enter`
once but claude code v2.1.126 with bracketed paste needs a second
Enter (the first closes the paste, the second submits).

**Fix shape (locked by eng review 2026-05-04):** add an
`extra_enter: bool = False` kwarg to
`TmuxTextSender.send_text(pane_id, text, *, extra_enter)` at
`lib/terminal_runtime/tmux_send.py:24`. When True, after the
existing `send-keys ... Enter` (line 57), sleep `CCB_TMUX_ENTER_DELAY`
(default 0.5s — same env var the existing fire uses) and send a
second `send-keys ... Enter`. Caller (the agent runtime layer
that owns provider awareness) sets `extra_enter=True` for claude
panes only. TmuxTextSender stays provider-agnostic.

Tests:
1. `test_terminal_runtime_tmux_send.py` — add a case for the
   default `extra_enter=False` branch (codex path) asserting
   exactly 1 `send-keys Enter` call.
2. `test_terminal_runtime_tmux_send_extra_enter.py` (new) —
   `extra_enter=True` asserts 2 `send-keys Enter` calls separated
   by the configured delay; assert delete-buffer still fires
   in the finally clause.
3. Caller integration: assert agent runtime invokes `send_text`
   with `extra_enter=True` for claude provider, False for codex.

### Issue 3 — cmd pane "target pane has exited"

**Diagnostic plan (one round):**
1. Probe ccbd to log the actual `cmd_pane_id` value the dispatcher is
   sending to. Add a one-shot `_logger.warning` at the entry of
   `_deliver_cmd_replies` printing `discovered_cmd_pane_id` and the
   `is_alive` result.
2. Compare against startup_report.json `bootstrap_cmd_pane`.
3. Confirm whether discovery returns a stale id, an inactive
   window-target, or correct `%2` that fails for a different reason.

**Likely fix shapes (TBD post-diag):**
- A) Tighten cmd pane discovery to always re-resolve via the
  `__ccb_ctl` window's pane title rather than caching across restarts.
- B) Skip-on-stale: if `is_alive` returns False, refresh discovery
  cache and retry once before failing.
- C) State file invalidation on `ccb kill -f`: clear the cached
  cmd_pane_id during teardown so post-restart discovery starts fresh.
